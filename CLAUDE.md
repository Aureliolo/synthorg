# CLAUDE.md: SynthOrg

Framework for synthetic organisations (role-based AI agents run as a supervised company, under an oversight mode the operator sets). Python 3.14+. BUSL-1.1 to Apache 2.0 after the Change Date. Layout: `src/synthorg/` (src layout), `tests/`, `web/` (React 19), `cli/` (Go binary), `evals/` (golden-company benchmark, out-of-package).

Web: see `web/CLAUDE.md`. CLI: see `cli/CLAUDE.md` (`go -C cli`, never `cd cli`). Shell / `cd` / file-write rules: see `~/.claude/rules/common/bash.md`.

## MANDATORY rules

Each rule's full rationale, exemptions, and gate internals live in the linked reference; the line here is the contract.

- **Design Spec (MANDATORY)**: read the `docs/design/` page before implementing; deviations need approval. See [DESIGN_SPEC.md](docs/DESIGN_SPEC.md).
- **Planning (MANDATORY)**: present every plan for accept/deny before coding.
- **Web Dashboard Design System (MANDATORY)**: reuse `web/src/components/ui/`; design tokens only. See `web/CLAUDE.md`.
- **Frontend Is A Pure API Consumer (MANDATORY)**: the dashboard persists NO app/domain state client-side (no `localStorage`/`sessionStorage`/IndexedDB, no `zustand` `persist` as a source of truth). Backend is the sole source: hydrate via GET, write every change through the API, every feature usable over the API alone. Client storage only for transient non-domain UX (auth cookie shim, CSRF token). Gate `check_no_client_state_persistence.py`. See `web/CLAUDE.md`.
- **Regional Defaults (MANDATORY)**: no region/currency/locale privileged; metric units; British English. See [regional-defaults.md](docs/reference/regional-defaults.md).
- **Persistence Boundary (MANDATORY)**: only `src/synthorg/persistence/` may import sqlite/psycopg or emit raw SQL; new repository protocols inherit a generic category from `persistence/_generics.py`; bespoke methods only under ADR-0001 D7; protocols stay `@runtime_checkable`. See [persistence-boundary.md](docs/reference/persistence-boundary.md).
- **Convention Rollout (MANDATORY)**: every convention PR ships its enforcement gate. See [convention-gates.md](docs/reference/convention-gates.md).
- **Signing-Identity Pins (MANDATORY)**: keyless signing derives the certificate SAN from `job_workflow_ref`, which for a `workflow_call` job is the reusable workflow's own path, NOT the caller's, so the SAN names the build RECIPE and is shared by every caller on GitHub. A verification policy therefore pins BOTH the SAN regex (`ExpectedReleaseSANRegex` for release archives, `ExpectedSANRegex` for images, both in `cli/internal/verify/identity.go`, and neither constructor takes a pattern from its caller: a supplied regex carrying a second top-level alternative still opens with the repository prefix and closes with the anchor, so it cannot be validated into safety) AND repository-binding extensions (`SourceRepositoryURI` + `SourceRepositoryIdentifier` + `RunnerEnvironment`, via `verify.BuildIdentityPolicy`); SAN alone would accept an artefact signed by anyone who called our public reusable workflow. Each pin admits its artefact class's current signers plus names declared retired (a published signature cannot be re-minted), each bound to the ref class it legitimately produces: tags for release archives, `heads/main` for images (publish jobs are main-gated and retagging re-signs nothing). Rejected: a caller-only filename, a signer for one class admitted by the pin for the other, a retired name unbounded beyond the versions it signed, and an unclassified new signing path, which must be pinned or declared as signing something the CLI never verifies (the apko base layers, absent from `ImageNames()`). Signers are derived from the workflow tree, transitively through composite actions and shell helpers, and each Go constant must equal character-for-character the pattern its declaration builds, because a partially-validated regex leaves the unvalidated part free. Enforced by `check_signing_identity_pins.py`. See [security.md](docs/security.md).
- **License Compatibility (MANDATORY)**: no AGPL/GPL (non-LGPL) dependency ships; LGPL deps (Python `psycopg*` and any LGPL JS package in `web/package-lock.json`) attributed in `NOTICE`; `golangci-lint` stays an external binary; `pymupdf`/`fitz`/`pymupdf4llm` excluded. A dependency offered under an SPDX DISJUNCTION (`A OR B OR C`) is an offer of alternatives, not a stack of obligations, so it is classified on the arm a licensee would elect and that election is recorded in `NOTICE` (`tld`, reached transitively through `trafilatura` -> `courlan`). Splitting must be on the space-delimited operator: `GPL-3.0-or-later` is ONE licence whose name contains `or`, and tearing it apart passes the strongest copyleft there is as permissive. Because the direct-dependency scan walks `pyproject.toml` only, an electable TRANSITIVE dist is named in `_ELECTED_DISJUNCTIVE` or nothing classifies it at all, and the gate then re-checks on every run that the offer still reaches the elected arm: a version bump can drop the arm while the package name never moves, which a name denylist cannot see. Enforced by `check_license_compat.py`. See [license-policy.md](docs/reference/license-policy.md).
- **Configuration Precedence (MANDATORY)**: DB > env > code default (Cat-1) or env > code default (Cat-2); Cat-3 bootstrap secrets are pure env. No `os.environ.get` outside startup (single-key reads only in the bootstrap / entry-point / dynamic-secret / Cat-3 allowlist or behind `# lint-allow: env-read`). Enforced by `check_no_os_environ_outside_bootstrap.py`. See [configuration-precedence.md](docs/reference/configuration-precedence.md).
- **Compose-Set Or Live (MANDATORY)**: a setting is EITHER fixed when a process starts (`compose_set=True`, write rejected, shown read-only in the dashboard) OR it applies while the system runs. There is no third category, so there is no restart control and no pending-restart state. `compose_set` is reserved for what the process genuinely cannot change about itself (bind address, TLS material, the sandbox image the CLI verified, the TSA trust anchors resolved before the settings backend exists), and every one must be passed by every shipped launcher that starts its reader: `check_setting_compose_backed.py` fails a `compose_set` key unless `cli/cmd/worker_start.go` sets it (worker-only) or BOTH `cli/internal/compose/compose.yml.tmpl` and `docker/compose.yml` do (backend), so the label cannot become "we did not wire this up". Everything else goes live by the mechanism its consumer allows: a per-call resolver read, a `set_*()` setter + subscriber, a bridge snapshot, a runtime rebuild (`RuntimeReloadSettingsSubscriber`), or a subsystem `settings=` declaration the reconciler rebuilds on. The sibling gate `check_setting_live_or_compose_set.py` enforces the complement: a writable setting that no subscriber `_WATCHED` pair, `SubsystemSpec` declaration, live resolver read or dashboard reference reaches IS the third category, and a read that runs only while the runtime is assembled is not liveness. Assembly is DERIVED, not listed: every `synthorg.workers` module reachable from the one defining `build_runtime_services` (a hand-listed pair had already gone stale by twelve), plus any subsystem `activate=` / `deactivate=` target. A spec's `enabled_by` always counts because the reconciler evaluates it every pass, but its `settings=` counts ONLY with `rebuild_on_change=True`: without the flag the reconciler short-circuits on an already-active subsystem, so the write is watched and applied to nothing. Dashboard evidence needs the namespace AND the key quoted in one non-generated file, since eight settings are keyed `enabled` and one stray token would otherwise certify all eight. A **blank-default** setting is judged on cold-start evidence only, because the write that matters for it is the FIRST one: two otherwise-valid shapes are refused, a read supplying a fallback (it sits inside the component the setting decides whether to build and falls back to that component's build-time pair, so it can move a running instance to a different model but never bring one up) and a namespace-wide bulk read (it names the namespace, not the key, and here feeds a boot config snapshot). Between them those masked a per-feature model that was written, persisted, shown in the dashboard, and applied to nothing until a restart. What still counts is a declaration or a read with nowhere to fall back to (`resolve_bound_model_live` + `require_configured_model`), where unset fails loud so the first write arms the next call. There is deliberately no per-line opt-out; pre-existing violations live in `scripts/setting_live_or_compose_set_baseline.txt`. Security-weakening writes still need the confirm+reason guardrail (`settings/write_governance.py`). See [configuration-precedence.md](docs/reference/configuration-precedence.md).
- **Subsystem Reconciliation (MANDATORY)**: wiring is declared in `api/subsystems/registry.py` and driven by a level-triggered reconciler, never sequenced by hand. A subsystem declares what it `requires` and `provides` (liveness is read from `provides`, so "up" cannot drift from what activation installed), plus the `settings=` its activation bakes in; boot is the first pass and every trigger (settings write, periodic resync) is the same idempotent pass with a different label. A dependency absent at boot is not a verdict: the next pass picks it up. `rebuild_on_change=True` needs a `deactivate` (a rebuild is teardown-then-activate; without one the promise silently never fires) and the graph refuses the declaration otherwise. `GET /subsystems` reports each phase and, when waiting, every unmet capability. There is exactly ONE wiring path per declared subsystem: a second caller of a registry-activated `wire_*` (a post-setup rewire list, a settings subscriber re-running wiring, a composite wrapper) is the drift that stranded `wire_memory_backend`, so it is rejected; opt out per-line with `# lint-allow: subsystem-single-owner -- <reason>`. Enforced by `check_subsystems_single_owner.py`. See [subsystem-reconciliation.md](docs/design/subsystem-reconciliation.md).
- **Subsystem Decline Reason (MANDATORY)**: a subsystem that can decline names its own condition. `GET /subsystems` exists to answer "why is this not up", and an activation that returns without installing its capability leaves the reconciler nothing to report but "declined on a condition it does not declare; see the wiring log" (five of seven blocked subsystems answered that in a live run). A spec satisfies the rule three ways: it declares `settings=` (the reconciler reads them live and names a blank one), its activation chain raises `SubsystemDeclinedError` with the condition, or it cannot decline at all (no guarded bare `return` on an absence, so it installs or raises). An idempotency guard (`if already is not None: return`) is not a decline and needs nothing; the complement, an absence guard, does. The reconciler decides liveness from `provides` alone, so a declared reason supplies the WHY and never the WHETHER: an activation declining on its own idempotency guard while the capability is already installed still reads up. No baseline and deliberately no per-line opt-out: an activation that cannot name its condition IS the defect. Enforced by `check_subsystem_decline_reason.py`. See [subsystem-reconciliation.md](docs/design/subsystem-reconciliation.md).
- **Single-Owner Decisions (MANDATORY)**: every decision the loop makes has exactly ONE owner: never zero, never two. Two owners is a silent override, where the quieter authority wins and nobody is told (which model runs the work, what capability a model is, the plan's `task_structure`, the plan itself, whether the initiative is stalled, whether a call may carry `reasoning_effort`, whether a turn is empty, whether an initiative is authorised at all: eight observed cases). Zero owners is a deadlock, a state with no reachable exit and nothing watching for it. A legitimate multi-authority decision is an ordered precedence ladder with ONE resolver, never two answers (`DecompositionPlan.task_structure` is the worked example). The human is not an exception: "does a human need to decide this?" (owner: the escalation rule) and "what is the answer?" (owner: the human when the first says yes, the agent when it says no) are two separately-owned decisions, and a judge may only escalate, never de-escalate. This rule is deliberately NOT scripted: authority is a claim about intent that no AST can decide, and a gate that passed everything would be worse than the honest gap. Its decidable slices each have their own gate (`check_lifecycle_exit_reachable.py`, `check_subsystems_single_owner.py`, `check_no_ghost_attribute_read.py`, `check_single_planning_strategy_writer.py`); the general case lives in the inventory every new loop decision joins. `Plan.planning_strategy` is the worked example of the READER losing rather than one authority overriding another: it marks a SUBSTITUTION, so blank IS the researched answer, and a second writer stamping the shipped strategy's own name on every plan carried exactly as much information as stamping none, which refused every valid tree in a recursion-depth sweep. See [single-owner-decisions.md](docs/reference/single-owner-decisions.md).
- **No Ghost Lookups (MANDATORY)**: a `getattr(obj, "<literal>", <default>)` whose attribute name is declared as an attribute NOWHERE in `src/synthorg/` is a ghost read: the name exists on nothing we define, so the default is the only reachable outcome and the absent-branch below it is dead. Two shipped and were found by a live run, not by reading the code: `getattr(app_state, "tool_registry", None)` made a fail-closed tool-name validator reject every tool for the life of the process, and `getattr(state, "_connection_user", None)` recorded `api` as the actor on every audited write including authenticated ones, with a test that built the ghost shape so the suite agreed. A three-argument `getattr` is precisely the construct that hides an attribute read from mypy; written `obj.attr` both would have been rejected where they were written. The gate re-asks mypy's question at the level it can answer without inference (does this name exist on anything we define), and deliberately says nothing about whether it exists on THIS object, which is mypy's. Not flagged: two-argument `getattr` (it raises, which is the wanted posture), a non-literal name, `hasattr`, and `dict.get` (a dict is a partial map by construction). Opt out per-line with `# lint-allow: ghost-attribute-read -- <reason>`; the reason is mandatory because every legitimate case is a third-party read and that is the only place the fact gets written down. History lives in the shrink-only `scripts/ghost_attribute_read_baseline.txt`, keyed `path::qualname::attribute::count` (the count so a function approved for one cannot silently acquire a second), and a count that outlives its sites is reported as drift rather than tolerated. Enforced by `check_no_ghost_attribute_read.py`.
- **No Hardcoded Values (MANDATORY)**: numerics live in `settings/definitions/`; allowlist 0/1/-1, HTTP codes, hex masks, powers-of-2, and module-level annotated `NAME: Final[...] = literal`. Enforced by `check_no_magic_numbers.py`.
- **Argument-Count Cap (MANDATORY)**: `max-args = 8` and `max-positional-args = 5` (pinned separately: ruff defaults the positional cap to `max-args`, so an implicit one widens by inheritance). The population is derived from the AST of every tracked `*.py`, NOT from ruff's diagnostics: ruff exempts `@typing.override` syntactically and never visits a file pruned by `exclude` / `extend-exclude` / `.gitignore`, so trusting it would lose real over-cap functions (it lost three, one taking 13 arguments). Ruff classifies; the gate decides scope. Every function over EITHER cap must already sit in `scripts/argument_count_suppression_baseline.txt`, keyed `path::qualname::arity` (the arity so widening an approved signature costs a fresh approval), which only shrinks. There is deliberately no `lint-allow` opt-out; a new entry needs `ALLOW_BASELINE_GROWTH=1`, i.e. explicit user approval. Rejected outright: a file-level `# ruff: noqa` covering either rule, a tree-wide `lint.ignore` of either, a `[tool.ruff] extend` indirection, a nested `ruff.toml`, any raise of `max-args`, and two functions minting the same key. A `per-file-ignores` entry is allowed (framework-shaped Litestar and pytest signatures keep theirs) because discovery finds the function regardless and it still needs its baseline row. Enforced by `check_argument_count_suppression.py`.
- **Explicit Provider Binding (MANDATORY)**: a provider is a registered *connection*, with its own credentials, endpoint and quota, so the same model id reached through two of them is two different calls, billed and rate-limited separately. Every LLM dispatch therefore names BOTH halves: its own `(provider, model)` pair, from its own `SettingType.MODEL_REF` setting (which rejects a provider-less value at write time). There is no shared default to borrow and no auto-pick to fall back on: `providers.default_provider` and the whole `ProviderRegistry.{default_provider,default_provider_name,default_provider_resolved_name,bind_default_provider}` surface are deleted, and a feature whose pair is unset is OFF and says so (or raises a 503 naming the setting, via `require_configured_model`). A system feature reads its pair live per call through `resolve_bound_model_live` + `require_configured_model`, or at wiring time through `resolve_bound_completion` into a `BoundCompletion` (the client and the model id travel together so a caller cannot pair a client for one connection with an id chosen for another). Two gates, neither with a baseline: `check_no_provider_auto_pick.py` rejects `list_providers()[0]` / `names[0]` / `resolve_for_model` / any reintroduced default-provider surface (per-line `# lint-allow: provider-auto-pick -- <reason>` for a non-dispatch use), and `check_explicit_model_binding.py` rejects a non-blank default on a model-shaped field or `MODEL_REF` setting, plus any `example-*` / `test-*` placeholder identifier reaching a *value* rather than prose (docstrings and `description=` / `examples=` / `note=` / `title=` / `help=` are the only positions that may name one). `check_explicit_model_binding.py` has deliberately NO per-line opt-out: an escape hatch is how nine production call sites came to ship placeholder model ids, so a genuine exception changes the shape (read a `MODEL_REF`) rather than silencing the check. A **system feature** is the one place a second pair is admissible, and only because an operator wrote both halves of it down: see Declared Failover Pairs below.
- **Declared Failover Pairs (MANDATORY)**: the ONE admissible second pair, and only for a system feature's `MODEL_REF` binding. A system feature has no employee to mark out when its connection stops serving; an agent does (it goes unavailable and its work is reassigned, `engine/roster.py`), and the gateway does too (its pair is minted per run from verified claims), so neither fails over and both are out of scope by ruling rather than by omission. The operator writes BOTH halves into `providers.failover_routes` and resolution is an exact-key lookup on `provider/model_id`: nothing is sorted, indexed, ranked or scanned, so no arrangement of the registry can produce a fallback nobody chose, and a pair with no entry reads exactly like the feature being off. It ships off (`providers.failover_enabled`), and both keys are governed writes: enabling widens what may answer a bound request, and a route is guarded on ADDITION keyed `declared -> alternate`, so repointing an existing pair at a different connection is a fresh grant rather than an edit that slips past a toggle somebody flipped months ago. Two triggers, neither silent: **pre-flight** (the declared pair's recent window already reads unserviceable, so it is not tried, which is what stops a feature paying the full retry ladder against a pair taking 311 seconds to refuse) and **retry once** on `internal` / `overloaded` / `rate_limit` / `payment_required` / `timeout` / `connection` (an invalid request, a bad key, a content filter or an unknown model would fail identically on the alternate, so retrying there is pure latency). Streaming gets pre-flight only: a stream that failed partway has already handed chunks to the caller. Every engagement logs `PROVIDER_FAILOVER_ENGAGED` AND persists a `provider_failover_events` row recording both pairs in full, because "the alternate" identifies nothing once the map has been edited, and the log does not survive the restart the question outlives. Cost needs no new code: the alternate's own driver builds the `CostRecord`, so the row names what actually served. Enforced by `check_declared_failover_pairs.py` (AST, no baseline, per-line `# lint-allow: declared-failover -- <reason>` with a mandatory reason, matched anywhere in the offending statement's line span because a trailing comment sits on its LAST line): inside `providers/failover*.py` it rejects an indexed computed sequence, `next(...)`, a `.values()` / `list_providers` scan and any agent-identity reference; it rejects importing any of them from `memory/`, the gateway package or anything named `embedder`, in every import shape, which means resolving each one to an absolute path first (`from synthorg.providers import failover` names the package and puts the module in an alias, and `from ..providers.failover import x` names neither, so comparing the written text left the rule bypassable by an import style twice over); and it allows `FailoverCompletionProvider` to be constructed in `providers/model_binding.py` alone, under any spelling, because importing the module and calling `failover_dispatch.FailoverCompletionProvider(...)` builds the same object. The enforced module set is DERIVED from that glob rather than listed, because a list is one module away from disagreeing with the pattern it claims to enforce, and an empty match fails the gate closed. See [providers.md](docs/design/providers.md).
- **Operator-Chosen Embedder (MANDATORY)**: memory's embedding model is the operator's explicit choice (`memory.embedder_model`, a `MODEL_REF` whose type refuses a provider-less value); nothing ranks, recommends or auto-selects one, and the vector width is measured by probing the model, never read from a shipped table. The built-in `builtin/hashing` embedder is lexical, not semantic, and is reachable ONLY by naming it: no path may substitute it for a model that failed, went unreachable, or was left unset, and no embedder may be constructed inside an `except` handler. Unresolved means memory stays OFF and says so. A width above pgvector's HNSW ceiling is DEGRADED (correct results, exact scan), never unready. Opt out per-line with `# lint-allow: no-silent-embedder-fallback -- <reason>`. Enforced by `check_no_silent_embedder_fallback.py`. See [memory.md](docs/design/memory.md).
- **LLM Gateway Binding (MANDATORY)**: the OpenAI-compatible LLM gateway (`api/gateway/`, fronting the in-process `ProviderRegistry` for an embedded harness) resolves its `(provider, model)` pair from the verified per-run token claims (`claims.provider` / `claims.model_id`), NEVER the request's `model` field, and never auto-picks; dispatch runs under `cost_recording_scope` and a hard token-budget kill. Opt out per-line with `# lint-allow: gateway-binding -- <reason>`. Enforced by `check_gateway_explicit_binding.py`. See [llm-gateway.md](docs/design/llm-gateway.md).
- **Credentialed-MCP Governance (MANDATORY)**: the credentialed-tool MCP invoke path (`api/mcp_gateway/tools.py::invoke_credentialed_tool`) must scope per actor (`visible_tool_names`), validate at the typed boundary (`parse_typed`), dispatch through the governed tool (`.execute`), and fence the result with `wrap_untrusted(TAG_TOOL_RESULT, ...)` so credentials and untrusted output never reach the harness ungoverned. Opt out per-`def` with `# lint-allow: credentialed-mcp-governed -- <reason>`. Enforced by `check_credentialed_mcp_governed.py`. See [credentialed-mcp.md](docs/design/credentialed-mcp.md).
- **Governed Destructive Tools (MANDATORY)**: a `GovernedConnectionTool` that destroys or replaces upstream state (a deploy release, not an opened issue) sets `_DESTRUCTIVE = True`, calls `require_admin_guardrails` as the lexically FIRST statement of `_check_preconditions` (which runs BEFORE the approval gate, so an unconfirmed or unattributable call is refused rather than parked for a human), and binds its own `_ACTION_TYPE` instead of inheriting the shared `comms:external`: sharing it would let an autonomy grant written for chat auto-approve a production deploy. A read-only tool on a destructive family's connection keeps the family action type without the flag. Opt out per-class with `# lint-allow: governed-destructive -- <reason>`. Enforced by `check_governed_destructive_tools.py`. See [credentialed-mcp.md](docs/design/credentialed-mcp.md).
- **Confined Auto-Approval (MANDATORY)**: an autonomy preset grants bare categories (`"code"`, `"docs"`), so its auto-approved set is not a list anybody wrote: it is whatever the taxonomy contains when the resolver expands it. Every concrete type a built-in preset auto-approves must therefore be declared in `security/action_types.py::WORKTREE_CONFINED_ACTION_TYPES`, a claim about where the action LANDS rather than how the verb sounds (`code:delete` qualifies, deleting a file in a directory nobody keeps; `design:delete` does not, the asset store outlives the run). Two grants had already widened silently under the old shape: `ToolCategory.DESIGN` defaulted to `docs:write`, so granting `"docs"` also auto-approved a billed external image provider and asset deletion under a type the risk map scores LOW; and SEMI granted the bare `"vcs"`, which expands to `vcs:push`, the one verb that reaches a remote and the one SUPERVISED gates by name. The complement is runtime, not gated: bare-category expansion for auto-approve is built-ins only (`expand_category(..., builtin_only=True)`), because a grant cannot have meant a custom type registered after it was written, while the restricting `human_approval` side still sweeps them in. `"all"` is exempt by inspection: it is an explicit grant of everything and FULL's description says so. No baseline and deliberately no per-line opt-out; an exception is a line added to the declaration. Enforced by `check_autonomy_auto_approve_confined.py`. See [security.md](docs/design/security.md).
- **Forge Repo-Scoping (MANDATORY)**: forge agent tools are least-privilege and fail-closed. The scope check lives once in `_BaseForgeTool._resolve_connection`, which rejects any `owner/repo` outside the bound connection's persisted `allowed_repos` (`owner/repo` entries, `owner/*` globs; empty = deny every repo) with `ForgeRepoScopeError` BEFORE the approval gate. An operator selects the in-scope repositories per connection (scan via `GET /connections/{name}/accessible-repos`, persist on the `Connection`). No forge tool may override `_resolve_connection` without either delegating to `super()._resolve_connection(...)` or re-enforcing scope with its own reachable `ForgeRepoScopeError`; opt out per-class with `# lint-allow: forge-repo-scoped -- <reason>`. Enforced by `check_forge_repo_scoped.py`. See [agent-hands.md](docs/design/agent-hands.md).
- **Chat-Inbound Fencing (MANDATORY)**: inbound Slack Socket-Mode content is attacker-controlled human input, so the inbound package (`integrations/chat_api/inbound/`) never turns it into a prompt: it forwards a human reply ONLY as a resume `decision_reason`, which the resume machinery fences with `wrap_untrusted(TAG_TASK_DATA, ...)` (via `build_resume_message`) before any LLM boundary (the same path the dashboard approval comment takes). No inbound module may call an LLM-completion chokepoint (`complete_text`/`complete_structured_text`/`cost_recording_scope`/`.complete(`); the router must keep the `decision_reason=` hand-off on its actual `resume(...)` dispatch. Opt out per-call with `# lint-allow: chat-inbound-fenced -- <reason>`. Enforced by `check_chat_inbound_fenced.py`. See [chat-inbound.md](docs/design/chat-inbound.md).
- **Agent-MCP Visibility (MANDATORY)**: the agent MCP self-consumer (`engine/mcp_self_consumer.py`) scopes per agent, never a single global grant: an ELEVATED agent receives the ambient read/write surface out of the box but a sensitive (`domain:admin`) tool only when its own `ToolPermissions.mcp_capabilities` (or an operator-set `elevated_capabilities` broadening) grants it, so a prompt-injected agent cannot reach the high-blast-radius surface. The bridge must keep feeding `identity.tools.mcp_capabilities` into the capability set it passes to `visible_tools(...)`, not merely read it. Enforced by `check_mcp_self_consumer_scoped.py`. See [agent-mcp-governance.md](docs/design/agent-mcp-governance.md).
- **MCP Server NPM Pin (MANDATORY)**: a hand-authored `MCPServerConfig` running an `npx`-style package (`npx`/`pnpm dlx`/`bunx`) must pin an explicit version via `_validate_npm_pin` (a floating tag such as `latest`/`next` is not a pin), so a reconnect can never silently pull an un-reviewed package version past the catalog installer's pin. The validator must keep inspecting `self.command` + `self.args`, decide conditionally, and keep a reachable `raise ValueError`. Enforced by `check_mcp_server_config_pinned.py`. See [agent-mcp-governance.md](docs/design/agent-mcp-governance.md).
- **MCP Runtime Launchable (MANDATORY)**: a stdio MCP server is arbitrary third-party code, so it runs in a container, and there is exactly ONE image in this product that runs untrusted code: the resolved `tools.sandbox_image`, which the CLI verifies. `tools.mcp_sandbox_image` is deleted, because a second knob naming a second image is a second answer to which image an operator hardened, and its default named a third-party image the deployment had never pulled. The transport is `tools/mcp/container_stdio.py`, over the Docker API: it creates the container, attaches stdin+stdout BEFORE the start, and yields the same line-delimited-JSON stream pair the SDK's `stdio_client` does. The CLI is not an option (the hardened backend ships no `docker` binary, which is why the wrapper that shelled out to `docker run -i` failed identically to the direct spawn it replaced, and the whole `npm_package` half of the catalog had never launched on any shipped stack). - **Names, Never Ids (MANDATORY)**: an id is a database key, so no operator surface renders one. The backend resolves the name once per response and sends it beside the key (`src/synthorg/api/_read_names.py`: `agent_name_map`, `resolved_actor_name`, `task_titles`, `project_names`), which answer `None` when nothing names it and the surface then prints its OWN words (`UNKNOWN_AGENT_NAME`, `UNASSIGNED_LABEL`, `SYSTEM_ACTOR_NAME`), never the key. A leak happens at THREE boundaries and all three shipped, so all three are gated: the render (a UUID heading a cockpit row); the mapping layer filling a name-shaped field (`agentName: event.related_ids.agent_id`, whose render site reads perfectly, so a JSX-only rule cannot see it); and backend prose an event carries in its own `description` (`f"Task {record.task_id} started"`), which survives even once the name beside it is resolved. `check_no_raw_id_in_ui.py` fails a JSX text child or an `aria-label`/`title` ending in an identifier, a `*name`/`*title`/`*label` field assigned one, and a `*Event` `description` f-string interpolating one. Comments are blanked first, so `PATCH /agents/{id}` in a doc comment is documentation. Opt out per-line in the boundary's own comment syntax: `{/* lint-allow: id-in-ui -- <reason> */}` in JSX, `// lint-allow: id-in-ui -- <reason>` at a `.ts` mapping site, `# lint-allow: id-in-ui -- <reason>` on a Python event description; the reason is mandatory because every legitimate case is a claim that the value is human-readable and the marker is the only place that claim is written down. - **Output-Style Policy (MANDATORY)**: a configurable house writing style is injected into agent prompts (soft, org-wide with per-role/department override via `ScopeKind`), and a deterministic guardrail (no LLM) rejects or rewrites agent output violating a hard rule (the em-dash ban) via `enforce_output_policy`/`evaluate_output_policy`. Enforcement happens IN-SESSION at the tool through which the organisation keeps or sends something (file write/edit, living document, commit message, PR/issue body, inter-agent message, outbound chat send, outbound email, parked question, plan prose, charter interview, initiative evaluation verdict), so a refusal is that tool's own result and the agent fixes it on its next turn. The charter is BOTH halves of an interview turn, guarded on the parse of the model's reply where the strategy already asks for a correction: the question goes straight to the operator, and the draft becomes the persisted charter whose `proposed_project_name` names the project the whole run is delivered under. Its repair turn asks for a CORRECTED reply rather than the same content re-shaped, because a reply refused on its wording that is re-sent unchanged spends the one repair for nothing. Every boundary reaches ONE primitive, `engine/output_style/approval.py::approve_texts`, which answers a refusal STRING rather than a typed error because the boundaries share no error type; five hand copies of that loop is how one comes to reject where its siblings rewrite with nothing to notice. It scopes to what SHIPS: the agent's narration and reasoning are working state and are never gated, because a live run burned three rework rounds and 536,628 tokens on four em-dashes in a closing message and then failed the task for zero artifacts after its peer review had approved the work. Only what a write INTRODUCES blocks: both file tools subtract the blocking findings the target already carried (shared `tools/file_system/_output_policy_guard.py`), or an agent is refused over a character it did not author. Sameness across the two evaluations is keyed on the rule plus the match's SURROUNDINGS, never the match alone: a literal ban matches one character, so keyed on the snippet a write that removes one occurrence while adding another subtracts to nothing and quotes back the occurrence the agent did not write. It fails CLOSED past the per-evaluation finding cap, where both sides saturate, every subtraction is empty and the boundary would silently stop guarding the worst file in the tree. A chat send is reject-only even for prose (the approval gate parked a signature over the text a human read) and its refusal never carries the body back, since an outbound message routinely quotes third-party bytes and "send this instead" turns them into the next turn's instruction; a living document's literals (code body, metric value, URL) are reject-only because they take the CODE channel, where a punctuation swap corrupts a value. `emdash_literal` keeps `scan_code: true` and it is load-bearing: a code channel is one CODE span, so `false` would match nothing at the file-write boundary, which is the path the artifact takes. The post-session completion check (`engine/_review_oracle_gates.py::observe_output_policy`) is SHADOW-ONLY over the produced artifacts, one per declared path, never the narration; it returns nothing and takes no transition, so it structurally cannot reroute, un-approve or fail a task, and it exists because the OpenHands harness writes files inside the sandbox, out of reach of every in-session boundary. Three per-rule modes (reject-rework default, shadow, auto-rewrite-off-by-default); sanctioned exemptions are operator-scoped, never agent-self-granted; disabling/shadowing/adding an exemption routes through `write_governance`. Settings-driven, hot-reloadable, boot-wired (anti-ghost manifest). `check_output_boundaries_guarded.py` holds each boundary to its declared KIND: an `ENFORCING` one must call a guard, and the single `OBSERVING` one must additionally NOT call `enforce_output_policy`, since regaining the raising door there is exactly the shipped defect and nothing else would notice. See [output-style-policy.md](docs/design/output-style-policy.md).
- **Fail-Loud Execution (MANDATORY)**: in `engine/` + `workers/`, a broad-except handler that logs-and-continues must either surface the failure (re-raise, or raise a typed `DomainError`) or carry `# lint-allow: swallow-ok -- <reason>` on a genuinely failure-tolerant side channel (enforced by `check_no_engine_worker_swallow.py`). Separately, a work task (one that declares `artifacts_expected`) that produces zero artifacts terminates `NO_OP` to `FAILED`, never a silent `completed`/`in_review` success. Both halves of that guard are structural: `check_verified_completion_paths.py::_check_post_execution_guards` fails a post-execution transition that stops probing for artifacts or stops mapping an unfinished run to a terminal reason, and the `task_sync`/`react_loop` suites cover the behaviour the guard arms.
- **Verified Initiative Completion (MANDATORY)**: an initiative reaches COMPLETED only through the tail. Every plan item passing its own review gate opens INTEGRATING (one accountable, gated assembly task, `plan_id` set and `plan_item_id` unset) and then EVALUATING (a bounded lead-run session scoring every objective criterion, fail-CLOSED: no verdict parks the plan, never completes it). `EXECUTING -> COMPLETED` and `ACTIVE -> COMPLETED` do not exist; only `engine/initiative/evaluate.py` writes `PlanStatus.COMPLETED`; a WORK unit always declares an expected artifact so the zero-artifact guard arms. Opt out per-line with `# lint-allow: verified-completion -- <reason>`. Enforced by `check_verified_completion_paths.py`. See [initiative-tail.md](docs/design/initiative-tail.md).
- **Reachable Lifecycle Exit (MANDATORY)**: every state of every `core/` `StateMachine` reaches a terminal using only hops the writer can always take. A `StateMachine` declares `unconditional_targets` (statuses needing nothing the entity may lack: a reason the writer authors, never an assignee or a non-empty item DAG), and `check_lifecycle_exit_reachable.py` walks those hops alone, breadth-first. Plain terminal reachability is not the test and would have passed the defect: `FAILED -> ASSIGNED -> CANCELLED` is a path, but `ASSIGNED` needs an assignee a task that failed before assignment never had, so the row was unresolvable, its raw `ValidationError` escaped as a repeating 422, and its plan and project became undeletable too. Every stuck task status therefore carries a direct `CANCELLED`, and a tail plan status carries `FAILED`. The complement is behavioural, not gated: a state nothing watches is the same deadlock one layer up, so an all-dead plan is routed to a person or ended, never parked in silence (`engine/initiative/stall_route.py`: one open `initiative:stalled` decision when an approval store can hold it, and a plan FAILED with its stall reason when this deployment has nothing that can ask), and a `coordinate(...)` returning `is_success=False` fails the plan exactly as a raise does. No baseline, no per-line opt-out; an exception changes the declaration. See [initiative-tail.md](docs/design/initiative-tail.md).
- **Resumable Runs (MANDATORY)**: a run survives a restart, because restarting is an ordinary operator action (an upgrade, a settings change needing a rebuild, a crash the runtime restarts) and a plan's waves are driven by a background task that does not outlive its process. Edge-triggered dispatch was the whole mechanism: an operator approved a plan, a task was created, and once that task was gone NOTHING anywhere asked again. A live run ended with two subtasks at `in_progress`, one at `in_review` and a plan at `executing`, and the board went on showing work in flight with nothing behind it, permanently. `RunRecoveryReconciler` is the level-triggered answer, on the same shape as the subsystem reconciler: boot is the first pass and every later pass is the same idempotent question. It classifies EVERY plan status, because one it does not name is one nothing watches: terminal (nothing to do), awaiting a human (parked correctly), unfillable (a `PLANNING` shell whose decomposition died is FAILED with a reason, since the brief it was being written from is unrecoverable), driven (`APPROVED` / `EXECUTING`: requeue the orphaned rows, re-judge any task left `IN_REVIEW` with no open human decision against it, since a judging session that died mid-review leaves a row nothing else moves, then hand the waves back to the coordinator), and tail (`INTEGRATING` / `EVALUATING`: one rollup pass, because the stages key on a derived id and read their own state). Resuming re-enters the wave loop, so `gate_wave` gained the second half of its own question: it narrows to what still AWAITS DISPATCH as well as to what can deliver (and holds back, without parking, whatever awaits a person), since waves are rebuilt from the plan's items (what the plan WANTS) and would otherwise re-run finished work and then fail on it, `COMPLETED -> ASSIGNED` being refused. A wave left empty because everything already delivered is a SUCCESS phase, never the FAILED one an emptied-by-dead-inputs wave still records. Requeueing writes `INTERRUPTED`, the status that says what happened and the one the design already documented as "eligible for manual or automatic reassignment on restart"; the objective task is NOT requeued (the rollup derives it, and a second author of one value is the sibling defect), the assembly task IS (nothing else moves it, and the tail reads it as RUNNING for ever). `LiveRunLedger` is the one owner of "is this plan being driven in this process", claimed by both the approval path and the sweep so neither starts a second driver; it is in-process by construction and says nothing about another process, which is why a deployment running distributed workers requeues NOTHING (JetStream redelivery already owns a dead runner there, and a second answer could move a row a live worker holds). The approval path's shutdown compensation is now conditional on `shutdown_requested`: a stopping process leaves the plan alone for recovery, and every other cancellation still fails it. No baseline and no per-line opt-out; an exception is a line added to one of the declarations. Enforced by `check_run_recovery_covers_plan_statuses.py`. See [coordination.md](docs/design/coordination.md#graceful-shutdown-protocol).
- **Journalled Recordings (MANDATORY)**: a recording harness puts each finished cell on disk the moment it finishes, never at the end. The product's answer to a restart is `RunRecoveryReconciler` (see Resumable Runs); this is the same rule for the thing that MEASURES the product, where the stake is different: a cell is minutes to hours of real provider spend and, unlike a run, nothing can re-derive it. A live recursion-depth sweep spent seven hours, measured one cell, and a second process started after it was killed had written nothing at all; `evals/loop_ab/` accumulated its whole matrix in one list comprehension with the identical exposure. `evals/harness/journal.py` is the ONE owner of the mechanism: append, flush, `fsync`, a header naming the matrix, and a crash-truncated LAST line dropped with a warning while a broken line anywhere EARLIER is refused as corruption (reading past it would silently drop a cell already paid for). JSON Lines because that is the shape that survives a kill; a rewritten JSON document loses the lot. A harness binds it in `evals/<name>/journal.py` supplying only what is its own: how a cell is keyed (ONE owner of that format, since a resume matches on the string alone and two spellings re-run everything), what identifies its matrix, and which cells a resume buys back. That last is deliberately asymmetric: a MEASURED cell is read back, an UNAVAILABLE one is attempted again, because it cost almost nothing and the operator restarting has usually just fixed the reason it failed, so replaying it hands back the broken report they restarted to escape. The GRANULARITY is the unit of loss, not the unit of reporting, and a cell is the wrong one: a recursion-depth cell plans a tree, builds every leaf in its own container, assembles every node from the bottom up and grades the root, which is tens of sessions and hours, so a cell killed at hour six wrote its plan, its leaves, and its spend nowhere. Every SESSION is therefore journalled the moment it returns (`progress.jsonl`, beside `cells.jsonl`), carrying the tree on the planning row alone, because the units on disk belong to that tree and its objective's id is minted per call: re-deriving it leaves every `parent_task_id` naming a task that no longer exists. A resume needs BOTH halves and they are lost separately, so `_continue_cell` takes up an attempt only when the plan is journalled AND every unit it recorded still has its tree under the work root; either missing restarts the cell whole, since a plan without its trees would hand a merge empty directories and record the assembly as having delivered nothing. The session rows are also the SPEND ledger and the only one: the sweep books its ceiling at the same three points it records one, a cell row is those same sessions added up again (so reading both double-counts), and reading the cell rows alone misses every session of a cell that never finished, which is money gone from the account whichever attempt spent it. The header refuses a resume against a different commit, manifest, spec or pair BY NAME rather than mixing two matrices into one curve, and refuses another harness's journal by `journal_kind`; an existing journal is never silently overwritten. A cell is remembered and written by ONE call (`RecordedCells.add`), because a driver records from several branches and a journal call beside each append is one chance per branch to add another that only remembers. Out of scope by ruling rather than omission: a runner whose cells are free and reproducible (`evals/run.py` replays a cassette or a scripted strategy and makes no paid call), where a journal would be ceremony. The population is DERIVED, never listed: a module under `evals/` named `runner.py` that calls a report constructor IS a recording driver, and a hand-written list of harnesses is one new harness away from disagreeing with the set of things that record. An empty derived set fails closed. No baseline and deliberately no opt-out: a recording that can lose paid cells IS the defect. Enforced by `check_recording_harness_journalled.py`.
- **Cost Attribution Purpose (MANDATORY)**: every `cost_recording_scope()` call passes `purpose=` (a `PromptPurposeId` from `llm/prompt_purpose.py`, or explicit `None` when the call has no registered system prompt purpose) so cost attribution by prompt purpose cannot silently regress; opt out per-line with `# lint-allow: cost-scope-purpose -- <reason>`. Enforced by `check_cost_scope_purpose.py`.
- **No Synthetic Cost Owner (MANDATORY)**: `CostRecord.agent_id` / `.task_id` name rows that exist (`task_id` is a real FK into `tasks`), so a cost chokepoint (`cost_recording_scope` / `CostRecord(...)` / `complete_text` / `complete_structured_text`) never receives an invented id: no string literal, f-string, `NotBlankStr("...")` wrapper, or `or "system"` fallback. Work the system does for itself belongs to no agent and no task, and `None` is the honest value; what the call was FOR belongs in `purpose=` / `call_category`, not smuggled into an owner column. A fabricated id matches no row, so the insert fails the FK and the recorder swallows it, silently under-reporting spend. Opt out per-line with `# lint-allow: synthetic-cost-owner -- <reason>`. Enforced by `check_no_synthetic_cost_owner.py` (AST, deliberately no baseline).
- **Persisted Enum Vocabulary (MANDATORY)**: a `StrEnum` whose members are written into a column guarded by `CHECK (col IN (...))` declares its vocabulary three times (Python, plus one `schema.sql` per backend), and nothing kept them in step: `BlockedReason.NO_CAPABLE_AGENT` shipped, was written by two production paths, and appeared in NEITHER backend's CHECK, so a subtask nobody could take was never parked at all (the write violated the constraint, the row kept its old status, and a live run ended with two subtasks at `created` with nothing watching them and no exit, which is the exact state the park exists to prevent). `check_schema_drift.py` cannot see this: it compares `schema.sql` against the revisions, and both agreed because both were wrong together. The gate asks the question neither asks, does the column admit what the enum can produce, and answers it by value-set matching rather than a declared column-to-enum map, which would be one rename from lying. Scope is deliberately narrow: only a CHECK whose ENTIRE body is `col IN (...)` (optionally behind `col IS NULL OR`), because a conditional invariant (`(status = 'pending' AND decided_at IS NULL) OR (status IN ('approved','rejected') AND decided_at IS NOT NULL)`) names a subset on purpose and reading eleven of those as vocabularies would bury the one real defect; a `NOT IN` exclusion list and a single-literal constant are out for the same reason. An exact match to any enum passes even when a larger enum also contains the set (`risk_level IN ('low','medium','high','critical')` is `RiskLevel` entire). A CHECK admitting a value no enum declares is dead SQL vocabulary, fails no write, and is not this gate's question. Opt out inside the CHECK's own statement with `-- lint-allow: enum-check-parity -- <reason>`; no baseline, because a value the database refuses is never something to preserve. Enforced by `check_enum_check_constraint_parity.py`.
- **Dependency-Gated Waves (MANDATORY)**: a plan's DAG decides WHEN a subtask runs; whether it SHOULD, given that its declared inputs may have died, is a separate decision with ONE owner, `gate_wave`, which narrows a wave to what can deliver and parks each of the rest BLOCKED under `DEPENDENCY_FAILED` naming what it waited on. A wave empties THREE ways that must not be confused, so a dependency BLOCKED on a reason someone will still end (`ATTENDED_BLOCKED_REASONS` in `core/task_enums.py`: an escalated review, an unstaffed gate role, no capable agent) is a third outcome and not the second: its dependent has not failed, so it is neither dispatched nor parked, it is left at `CREATED` and counted in `GatedWave.awaiting`, and a wave emptied that way records a phase that is NOT the FAILED one an emptied-by-dead-inputs wave records. Parking it would tell a replan its inputs died when they are waiting on a person, and that reason is a replan's input (a wave left with nothing records a FAILED phase rather than vanishing, because a phase list that omits the level lets a rollup read the run as still working). The gate exists because the rule was first added to two of the three wave loops the product ships: `SasDispatcher` and `WaveDispatcher` share `execute_waves`, `ContextDependentDispatcher` carries its own copy of the loop, and it is the one a live run selected, so wave after wave dispatched onto work that had already failed while the unit suite stayed green (every test exercised a dispatcher that gated). Gating covers the wave being dispatched and nothing else, so it has a second half with the same owner: `abandon_after` parks every subtask of the waves a run STOPPED before reaching, under the same reason, because the alternative is what a live run left behind: three items failed, the loop broke, and two rows of an unreached wave sat at `created` that no dispatcher would run, no gate would park and no rollup could conclude on, so the plan read `executing` for ever and its project could not be deleted. Only a row still awaiting dispatch is abandoned; anything that ran owns its own outcome and anything already parked keeps the reason naming its actual dependency. A THIRD call has the same owner, `abandon_stranded`, for the wave that stopped the run: `abandon_after` skips it deliberately, which is right for a wave that RAN (it owns its outcome) and wrong for one that RAISED, because `persist` gives up on the first refused hop and the release reverts only the rows it had already moved, leaving the rest at `created`, which `NON_DELIVERING_STATUSES` does not contain, so the next wave's gate reads them as still on their way. What a park SAYS is a separate question from whether it happens: an execution group is one round of AGENTS, not one level of the DAG (`_rounds_by_agent` splits a level across as many groups as its busiest agent needs, and a fully-unroutable level emits none), so the groups after a stop are a MIX of work genuinely below it and siblings of it whose declared inputs are untouched. Both park, because a row at `created` has no exit; only the first is `DEPENDENCY_FAILED`, and the rest take `RUN_STOPPED`, since a replan reads these reasons and a dependency failure that never happened is a lie it acts on. Telling them apart needs `ParallelExecutionGroup.dag_level`, because a group's position in the sequence cannot give its level back. A FOURTH call, `abandon_unreachable`, covers what the other three structurally cannot see: all three reason about waves that EXIST, and `build_execution_waves` drops a subtask routing could not place plus everything transitively standing on it into a set local to the build, so those rows appear in no group at all and sit at `created` for ever while a recovery sweep re-drives the plan every cadence and changes nothing (a live run left two). Its set is DERIVED from the plan's own subtask ids minus the ids the built groups carry (the dependency map's keys ARE the subtask set, so the loop needs nothing new out of the builder and no second list can disagree with what was built). Parking is LEVEL-triggered throughout, including the unroutable park in `service.py`, which routing re-asks on every pass: a row that already carries an outcome is left alone, because `blocked -> blocked` is not a hop and the row's existing reason names its actual dependency, and because a refused mutation is a RESULT rather than a raise, so a `try/except` around the submit covers only the failures that cannot happen and every real refusal was silent. The population is DERIVED, never listed: a module under `engine/coordination/` that CALLS `build_execution_waves` is a wave loop and must call `gate_wave`, `abandon_after`, `abandon_stranded` AND `abandon_unreachable` (or `execute_waves`, which calls each for its callers). Calls, not references, because the package barrel re-exports the builder and dispatches nothing; aliases are resolved first, so an import style cannot decide whether the rule applies. Reaching a gating helper counts only at import DEPTH ONE, in both spellings (`from . import parking` and `from .parking import x`): a relative import that walks further out names a module of another package whose calls this scan never reads, so crediting it puts an unrelated name in the sibling set and, where that package holds a module by the same name, credits a dispatcher with gate calls it never reaches, which passes an ungated wave loop. An absolute import qualifies on naming the scanned package instead, since that is a claim about where the module lives rather than how far up the writer reached. An empty derived set fails as a configuration error rather than passing, since it means the builder was renamed and the gate has gone blind. No baseline and deliberately no opt-out: a second answer to "will this subtask run" IS the defect. Enforced by `check_wave_dispatch_gated.py`. See [coordination.md](docs/design/coordination.md#coordination-pipeline).
- **Roster-Held Gate Roles (MANDATORY)**: the two roles that JUDGE finished work (`Completion Reviewer`, `Red Team`) are held by ordinary roster agents, selected per review, never built at boot. An identity built in place is registered nowhere, staffed by nobody and absent from `GET /agents/active`: "peer review" performed by something that is not a peer, holding a role no operator could grant, producing verdicts comparable to nothing. Selection is `hr/role_staffing.py`: ACTIVE holders of the role minus the executor, preferring whoever already worked the reviewed initiative (derived from the tasks that ran, never a stored roster) and logging every widening, then capability fit against what the TASK needs, judged by the single org-wide `CapabilityPolicy` so the bar is the same one selection applied to the work, FLOORED at the executor's own rung (stakes and complexity are proposed by the agent that decomposed the work, and the ladder prefers an exact match, so a bar without that floor lets the thing under review bid its own judge down): exact rung, else the nearest HIGHER, else the nearest LOWER logged as under-capability. Capability decides WHO reviews and never what model anybody runs: `engine.completion_oracle_reviewer_model` is retired and no adversary-model setting exists, because the selected agent's own bound pair IS the answer (`security.red_team_model` bound the adversary AND its grounding checker; it is now `security.grounding_model`, covering the checker alone, with the operator's value carried across by migration). The dispatched identity is a NARROWED copy (`engine/review_session.py`): STANDARD tools, no MCP capabilities, SUPERVISED, because an injection planted in the reviewed artefact runs inside the reviewing session and a roster agent carries whatever its day job needs. Judging authority is a property of the ROLE an operator can see and grant, declared by `role_is_gate_role`, never a flag on the identity. Unstaffed is FAIL-CLOSED on both gates and says so, parking the task on its own `BlockedReason` (`reviewer_unstaffed` / `red_team_unstaffed`, kept apart because filling one role releases nothing parked on the other); the GATE only parks, and `engine/review_staffing/reconciler.py` is what opens ONE approval-gated hire per role org-wide, releases the park AND re-drives the review (a release that only transitions strands the task: nothing watches IN_REVIEW and the hop clears `blocked_reason`, so it also leaves the sweep's own query). The built-in identity fallback is the tempting-but-regressive answer and is why `check_no_synthetic_agent_identity.py` exists: constructing an `AgentIdentity` anywhere in `src/synthorg/` is rejected outside the declared roster-construction paths (`api/bootstrap.py`, `hr/hiring_candidates.py`, `meta/chief_of_staff/console_identity.py`), where "constructing" covers the class under any local alias plus `model_validate` / `model_validate_json` / `model_construct` on it, and a declared path that stops constructing one fails too, because an unused exemption is what the next construction inherits. Instance `model_copy` is deliberately not a construction: it derives from an identity already on the roster. Because a role now confers judging authority, the agent MCP surface refuses to grant a gate role at all (`agents.create` / `agents.update`), `agents.create` is admin-guardrailed like its delete sibling, and the MCP approvals door refuses to settle `org:hire` / `org:fire`; the operator's REST path grants roles and reaches the live registry rather than the config alone. No-self-review stays structural in both archives (`CHECK (executor_agent_id <> reviewer_agent_id)` and its red-team twin), both party columns are NULL when no reviewer ran rather than carrying an invented id, and each verdict row records the `(provider, model, capability)` the run committed to, which is the selected agent's own binding unchanged, so quality is comparable per agent AND per model. Every shipped template staffs a reviewer (`solo_founder` is three agents for exactly this reason); the security-hardened ones also staff a red teamer. Opt out per-line with `# lint-allow: synthetic-agent-identity -- <reason>`; deliberately no baseline. See [verification-quality.md](docs/design/verification-quality.md).
- **Sandbox Category Forwarding (MANDATORY)**: a sandboxed tool passes its own `category=` to `sandbox.execute`. That one argument decides BOTH the container runtime (a category may be pinned to gVisor) and whether the workspace mount is writable, and it defaults to the empty string, which resolves to "no category" and silently takes the global default for both. All five shipped call sites omitted it, so per-category runtime selection had never applied to any of them and a build stage reported `Read-only file system` on a workspace the design calls writable. The default cannot be dropped (callers outside the tool layer have no category to give) and a wrong category is worse than none, so the gate asks only that a tool forwards its own. A container's mount mode is separately fixed at creation while its category arrives per command, so the lifecycle owner key carries the mode (`<project>:<owner>[:img-<hash>]:<rw|ro>`) exactly as it already carries the environment image, and `release_owner` sweeps every mode. Opt out per-call with `# lint-allow: sandbox-category -- <reason>`. Enforced by `check_sandbox_category_forwarded.py`.
- **Workspace Sharing (MANDATORY)**: the backend and a sandbox are different POSIX identities on purpose (a sandbox that ran as the backend could act on the process governing it), so they share the backend's **group**, derived via `core/workspace_sharing.py::workspace_share_gid` and never configured: a configured gid is a second owner for a fact the OS holds, and a stale one fails silently back to no access. Files an agent writes are delivered through `delivered_file_mode`, which never narrows what a file already grants and widens an unreachable one by mirroring the owner's triad (`mkstemp` creates owner-only, which is invisible to the sandbox and made every captured test run fail `EACCES`); directories go through `ensure_shared_dir` at `0o2770`, group-write because an atomic replace needs the directory entry and setgid so what the sandbox creates stays readable to the backend. Nothing is granted to *other*. Git creates most of the tree itself, so `SHARED_GROUP_GIT_CONFIG` (`core.sharedRepository=group`) rides the one seam every system-internal git invocation already passes through rather than each `mkdir`. That seam also carries `NO_HOOKS_GIT_CONFIG` (`core.hooksPath` at a path holding no hooks), because the tree git runs in is one an agent can write: with the mount writable it can author `.git/hooks/post-checkout`, and the merge that follows runs `checkout` and `merge` in that tree AS THE BACKEND, which holds the docker socket, the database, and every other project. Disabling the host's config does not reach it; a repository's own hooks directory is consulted regardless. The container joins the gid via `GroupAdd` at creation, not through the image, so an operator's devcontainer override takes part without carrying our group; when the platform has no POSIX groups the absence is logged, never silent, because it leaves the sandbox unable to read the workspace at all. Enforced by `check_workspace_share_modes.py`. See [agent-execution.md](docs/design/agent-execution.md).
- **No Bound-Pair Rewrite (MANDATORY)**: an agent is a fixed `(role, personality, model)` unit, so work needing more capability goes to a DIFFERENT AGENT and nothing in the loop re-points the pair an operator bound. Three mechanisms disagreed and are deleted: budget auto-downgrade handed the run a rewritten identity at the task boundary, quota degradation swapped the provider mid-dispatch (`DegradationAction.FALLBACK`, whose config key is refused on WRITE and stripped-with-a-report on READ: refusing a persisted one costs the operator the whole connection over an inert value, and the reader's job is to lose as little as possible), and the stakes router raised the requirement from coordination metrics that only exist after selection. Each read reasonable at its own call site, each left the run's recorded capability rung meaning nothing, and together they made "which model ran this" a question with three answers. The same signals (stakes, complexity, budget) are now inputs to SELECTION: `CapabilityPolicy` judges every candidate once and both selection and dispatch read that one verdict, the ladder prefers an exact rung then the nearest higher then the nearest lower (logged), and preferring the exact rung IS the standing cost discipline that replaced auto-downgrade, applied on every assignment rather than past a threshold. Budget keeps every hard stop; exhaustion refuses. Enforced by `check_no_bound_pair_rewrite.py` (AST, no baseline): a `model_copy(update=...)` naming `model` / `provider` / `model_id` / `capability`, read from a dict literal, the `dict(...)` keyword form, or a module-local name assigned one of those keys (the operator's own PATCH is written that way, and a literal-only check is one refactor from missing it); plus any `ModelConfig` construction, under any local alias and through `model_validate` / `model_validate_json` / `model_construct`, since minting a fresh binding is how a rewrite looks once it stops calling itself one. Four declared owners, each of which must STILL produce one or the gate fails: `api/bootstrap.py` (rehydrates the persisted choice), `hr/hiring_instantiation.py` (a new hire), `meta/chief_of_staff/console_identity.py` (the console), `api/services/_org_agent_mutations.py` (the operator's PATCH). Deliberately silent on an update mapping no static read can open; the construction half has no such gap. Opt out per-line with `# lint-allow: bound-pair-rewrite -- <reason>`. See [providers.md](docs/design/providers.md).
- **Charter-Authorised Initiative (MANDATORY)**: standing up an initiative commits the organisation to a body of effort and a budget, so there is ONE intake path and it ends at an operator approving a charter. A live run filed a plain sentence ("I'd like a Tetris-ish game") into the dashboard chat and got a project, a plan and a decomposition run with no question asked and no approval taken: the router's `propose` branch read "a work request" and provisioned one, so a classifier's guess was the whole authorisation. `plan_required` is the flag that forces that outcome, so the flag IS the decision, and it is now paired with the approval that authorised it: `WorkItem.charter_id` is required whenever `plan_required` is set, refused at the type level, which is what makes it structural rather than a convention every future adapter re-decides. The `propose` capability keeps steering work a charter already authorised and has no field left in which to ask for more (`ProposeDecision` is clarify-XOR-steer under `extra="forbid"`); `ConversationalPlanDispatcher`, its subsystem, its capability and its duplicate-suppression window are deleted, along with the reuse-a-project machinery that existed only because that path provisioned without a gate. Enforced by `check_charter_authorised_initiative.py` (AST, no baseline): any `plan_required=` keyword and any `model_copy(update=...)` naming it (a copy skips validation, which is how a second intake path looks once it stops constructing one; the mapping is read from a dict literal, the `dict(...)` form, and a module-local name), reporting the OUTERMOST call in a nest so one decision reports once. ONE declared owner, `meta/charter/dispatch.py`, which must still force one AND still pass `charter_id=` or the gate fails as a configuration error, because keeping the flag while dropping the binding is the regression that would otherwise surface as a 500 at request time. It also fails closed if `WorkItem` stops declaring `charter_id` or its validator stops raising, since that runtime refusal is what covers the constructions no static read can open (`WorkItem(**payload)`). Deliberately no per-line opt-out: a genuine exception is a second intake path, which is the thing forbidden. See [plan-review.md](docs/design/plan-review.md#conversational-entry).
- **Prompt-Class Metadata (MANDATORY)**: every prompt class that tags an LLM chokepoint (`cost_recording_scope` / `complete_text` / `complete_structured_text`) with a non-`None` `purpose=` exposes a `@property metadata -> ModelPinMetadata` returning `pin_for(self._PURPOSE_ID)`; pins live in the single declarative registry `llm/model_pins.py` (the source the dashboard and the drift benchmark both read). Opt out per-class with `# lint-allow: prompt-class-metadata -- <reason>`. Enforced by `check_prompt_class_metadata.py`.
- **Doc Numeric Claims (MANDATORY)**: in the fixed set of public docs `check_doc_numeric_macros.py` scans (README + the listed `docs/` pages), a digit literal next to a stat noun (tests/providers/agents/tools/domains/namespaces/...) or stat keyword must use `<!--RS:NAME-->` markers from `data/runtime_stats.yaml` (or a per-line `lint-allow: doc-numeric-macros -- <reason>`). See `data/README.md`.
- **Test Regression (MANDATORY)**: timeout/slow failures are source regressions; never edit `tests/baselines/unit_timing.json` or any `scripts/*_baseline.*` (PreToolUse-blocked). The `ALLOW_BASELINE_GROWTH=1` gate-baseline bypass needs explicit approval.
- **Post-Implementation + Pre-PR Review (MANDATORY)**: after an issue, branch + commit + push (no auto-PR; `gh pr create` is blocked); use `/pre-pr-review`, then once the PR exists run the `babysit-pr` skill until squash-merge. Do NOT run `/aurelio-review-pr` after `/pre-pr-review` (same local review agents, so redundant); `/aurelio-review-pr` is only for PRs that skipped `/pre-pr-review`. Fix everything valid; no deferring.
- **Module-Size Budget (MANDATORY)**: tiered LOC caps per `# module-kind:` header (controller 400, service/orchestrator 600, complex_service 1100, repository 500, adapter/integration 700, feature 100, code 500 default, tests 800; declarative/generated exempt). Enforced by `check_module_size_budget.py` + `check_no_growth_in_god_modules.py`. See [ADR-0006](docs/decisions/0006-tiered-module-size-policy.md).
- **Import Layering + Architecture Drift (MANDATORY)**: declarative `.importlinter` contracts (forbidden-only, no total-order layers) via `lint-imports`, plus 3 AST gates (raw-SQL boundary, DTO-leak, dependency-inversion). Graph smells gated by `check_architecture_drift.py` vs `data/architecture_report.json`; cold-import cycles by `tests/unit/test_cold_import.py` (keep hub `__init__` light; shared types in `core.*`/`execution.*` leaves). See [import-layering.md](docs/reference/import-layering.md).

## Code conventions (detail in [conventions.md](docs/reference/conventions.md))

- Comments are WHY only; no reviewer citations / issue back-refs / migration framing. Enforced by `check_no_review_origin_in_code.py` + `check_no_migration_framing.py`.
- No `from __future__ import annotations` (3.14 has PEP 649). PEP 758 except: `except A, B:` without parens unless binding.
- Type-only imports stay at module level (so typeguard resolves annotations at runtime); `if TYPE_CHECKING:` only for genuine cycle breakers.
- Type hints on public functions; mypy strict. Google-style docstrings. Line length 88; functions under 50 lines.
- Errors: `<Domain><Condition>Error` from `DomainError`; never inherit `Exception`/`RuntimeError` directly. Enforced by `check_domain_error_hierarchy.py`.
- Pydantic v2: frozen + `extra="forbid"` + `allow_inf_nan=False` on every frozen model (gate `check_frozen_model_extra_forbid.py`; per-line `# lint-allow: frozen-extra-forbid -- <reason>` / `frozen-allow-inf-nan -- <reason>`); `@computed_field` for derived; `UUID` (`default_factory=uuid4`) for entity PK `.id`; `NotBlankStr` for names + string FK fields.
- Args models at every system boundary; `parse_typed()` for every external dict ingestion. Enforced by `check_boundary_typed.py`.
- Immutability: `model_copy(update=...)` or `copy.deepcopy()`; deepcopy at system boundaries.
- Async: `asyncio.TaskGroup` for fan-out/fan-in; helpers catch `Exception` (re-raise `MemoryError`/`RecursionError`).
- Clock seam: `clock: Clock | None = None`; tests inject `FakeClock`. Services own `_lifecycle_lock`; timed-out stops mark unrestartable.
- Untrusted content (SEC-1): `wrap_untrusted()` from `engine.prompt_safety`; `HTMLParseGuard` for HTML.
- Repository CRUD: `save(entity)`, `get(id)`, `delete(id) -> bool`, `list_items(...)`, `query(...)` returning tuples.
- Datetime in persistence: `parse_iso_utc` / `format_iso_utc` from `persistence._shared` (reject naive); `normalize_utc` for already-typed.

## Logging (detail in [sec-prompt-safety.md](docs/reference/sec-prompt-safety.md))

- `from synthorg.observability import get_logger`; variable always `logger`. Never `import logging` / `print()` in app code.
- Event names from `observability.events.<domain>` constants; structured kwargs (`logger.info(EVENT, key=value)`).
- Error paths log WARNING/ERROR with context before raising; state transitions log INFO via `*_STATUS_TRANSITIONED` AFTER the persistence write.
- **Secret-log redaction (SEC-1)**: never `error=str(exc)` or interpolate `{exc}`; use `error_type=type(exc).__name__` + `error=safe_error_description(exc)`. Never `exc_info=True` or `logger.exception(...)` (frame-locals serialise secrets), enforced by `check_logger_exception_str_exc.py`; never OTel `span.record_exception(exc)`, enforced by `check_otlp_span_redaction.py`.

## API startup, MCP, Resilience

- **Startup lifecycle**: two-phase boot (construction wires synchronous services; on-startup wires persistence-dependent ones), with gated failure-tolerant wiring hooks and load-bearing ordering invariants. Full trace in [api-startup-lifecycle.md](docs/reference/api-startup-lifecycle.md).
- **MCP**: 247 tools across 22 domain modules under `meta/mcp/domains/`. Define `ToolHandler` + `args_model`; call `require_admin_guardrails()` on admin tools; route through service layers. See [mcp-handler-contract.md](docs/reference/mcp-handler-contract.md).
- **Telemetry**: opt-in, off by default. Every event property must be in `_ALLOWED_PROPERTIES`. See [telemetry.md](docs/reference/telemetry.md).
- **Resilience**: provider calls go through `BaseCompletionProvider` (retry + rate limit); never retry in driver subclasses. `providers.retry_max_attempts` (Cat-1) is the default `max_retries` only when a provider left its own at the `RetryConfig` default. Non-provider transient I/O uses `core.resilience.GeneralRetryHandler`, never a hand-rolled loop (carve-outs in [retry-patterns.md](docs/reference/retry-patterns.md)).
- **Conversational org interface**: ONE surface, `POST /meta/chat/turn` (`api/controllers/turn.py`), classifies each message to a `TurnIntent` and dispatches via `dispatch_turn` (`_turn_dispatch.py`) to the capability service; an EXPLAIN turn can stream over `/turn/stream` (`_turn_stream.py`) while every side-effecting intent defers back to the buffered idempotent endpoint (act never streams). Uncertainty degrades toward `explain`, never `act`/`charter`/`configure` (higher floors 0.85/0.8/0.85). Capabilities (explain-chat / propose / group-chat) and multi-voice default ON, live-gated per request via `ensure_feature_enabled` (`api/_feature_gate.py`) so `chief_of_staff.*_enabled` toggles take effect next request, no restart. Concern **routing** is gated differently: per-turn via `resolve_cos_autonomous_cap` (`_capability_gate.py`), requiring BOTH the off-by-default persona master `self_improvement.chief_of_staff_enabled` AND `chief_of_staff.routing_enabled`; so despite `routing_enabled` defaulting true, routing stays effectively OFF until the master is enabled. Agent-invite + direct-MCP acting stay OFF by default; direct MCP acting is FAIL-CLOSED without security governance. The **Operator Console** (`CONFIGURE` intent, `_dispatch_configure` -> `OperatorConsoleService` as the shared ELEVATED system console identity) configures the control plane conversationally under its own default-off `chief_of_staff.operator_console_enabled` toggle, is FAIL-CLOSED without security governance, and is buffered (never streamed) like `act`. Human content is persisted raw and fenced via `wrap_untrusted(TAG_TASK_DATA, ...)` only at the LLM prompt boundary (SEC-1); a `configure`/`act` instruction is additionally credential-redacted before it reaches the prompt, and out-of-band secret capture keeps a setup credential out of the transcript entirely.

## Testing (detail in [conventions.md](docs/reference/conventions.md))

- Markers: `@pytest.mark.{unit,integration,e2e,slow}`. Async `auto`. Timeout 30s global. Coverage 80% min.
- xdist `-n 8 --dist=loadfile` auto-applied via pyproject `addopts` (`loadfile` prevents the 3.14+Windows ProactorEventLoop leak).
- Windows: unit tests pin pytest-asyncio loops to `SelectorEventLoop` (per-conftest `pytest_asyncio_loop_factories` in `tests/unit/conftest.py`); subprocess-driving tiers shadow it with `ProactorEventLoop`.
- Test doubles (ladder in [test-doubles.md](docs/reference/test-doubles.md)): `FakeClock` for the Clock seam, `mock_of[T](**overrides)` for typed-boundary substitutions, `SimpleNamespace` for attribute-bags. Bare `MagicMock` at a typed boundary is blocked by `check_mock_spec.py`. Import from `tests._shared`.
- Entity ids from `tests._shared`: `as_uuid(label)` for `UUID` PK, `sid(label)` for string FK / wire form, `coerce_id` / `as_pk` to normalise; never bare `uuid4()` for a cross-referenced id.
- API test client: HTTP tests use `async_test_client` (`LoopAsyncClient`, portal-free); websocket tests use the sync `ws_test_client`. The Windows `socket.socketpair` retry wrapper in `tests/conftest.py` is a permanent guard for CPython 122797.
- Vendor-agnostic: the product privileges no LLM vendor, so project code/tests NEVER name one where a provider or model is being configured, dispatched to, defaulted to, or illustrated. Use `example-provider`, `test-provider`, `example-{basic,capable,expert}-001`. Allowed in `.claude/` and its `.opencode/` mirror (developer agent tooling, not product surface: an agent's `model:` names the model that actually runs it, so a placeholder there configures nothing), third-party imports, the declarative preset registries `providers/presets.py` + `tools/web/providers/presets.py` + `tools/web/providers/fetch_presets.py` + `integrations/connections/http_vendor.py`, `integrations/mcp_catalog/bundled.json`, `web/public/provider-logos/`. The rule targets vendor privilege, not the existence of proper nouns: citing third-party research (a published benchmark's result rows) names real models because a citation with the names stripped cannot be checked against its source. A citation stays a citation only while it reports; the moment it recommends, it is privileging a vendor and the rule applies again.
- Hypothesis: 10 deterministic CI examples; failures are real bugs (fix + add `@example(...)`). Flaky: NEVER skip/xfail; fix fundamentally (`asyncio.Event().wait()`, not `sleep`).
- Dual-backend conformance: `tests/conformance/persistence/` consumes the `backend` fixture (SQLite + Postgres); enforced by `check_dual_backend_test_parity.py`. Local Postgres: export `SYNTHORG_TEST_POSTGRES_*` to bypass testcontainers.

## Git

- Commits: `<type>: <description>` (feat/fix/refactor/docs/test/chore/perf/ci); commitizen-enforced. Branches `<type>/<slug>` from main. Squash merge; trailers (`Release-As`, `Closes #N`) go in the PR body.
- Signed commits required on protected refs.
- Pre-commit/pre-push hooks in `.pre-commit-config.yaml`; tool-call gates in `.claude/settings.json` PreToolUse.
- **Push budget (MANDATORY)**: a push must finish inside 300s (`BUDGET_SECONDS` in `scripts/git-hooks/_run-hook.sh`), which prints every run's duration and an OVER BUDGET banner past the ceiling. Over budget is a gate-scope defect to fix, never a cost to absorb: `mypy`/`pytest` scope to what changed (`run_affected_{mypy,tests}.py`, sharing `scripts/_prepush_scope.py`; a cross-tree question defers to CI and says so), and independent tools run concurrently in groups (`scripts/run_prepush_hook_group.py`, one `_GROUPS` entry per group; a tool belongs in one only if it writes nothing and depends on no sibling's output). Breadth alone also defers: past `_MAX_AFFECTED_TEST_FILES` (600, derived from a measured ~0.25s/file against the ~155s of budget pytest gets) the unit run goes to CI whole, because at that size the local run has stopped being a fast screen; all-or-nothing because every rule for picking a subset drops packages the change actually touched.
- A failed pre-push leaves a `<hook>-FAILED` marker under `synthorg-hooks/` that blocks the next push; after fixing the root cause, clear it with `bash scripts/clear_prepush_marker.sh` (never a raw `rm`).
- GitHub queries: `gh issue list` via Bash, NOT MCP `list_issues`.

## Workflow

- CLI is Docker-only (init/start/stop/status); features go in the dashboard + REST API.
- **Subagent models (cost safety)**: pin an explicit `model:` in every `.claude/agents/` definition (never omit / `inherit`), and pass an explicit `model` to every `Agent` spawn and Workflow `agent()` / `meta.phases[].model`: `haiku` for mechanical checks, `sonnet` for review/analysis, `opus` only for the heaviest reasoning.
